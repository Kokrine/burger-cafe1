# ჩემი ბურგერების კაფე

სასწავლო მათემატიკური თამაში 1–4 კლასისთვის. მოსწავლე მართავს ვირტუალურ კაფეს:
ყიდულობს ინგრედიენტებს, აწყობს ბურგერებს, ემსახურება კლიენტებს, ითვლის ხურდას,
შემოსავალს, ხარჯს და მოგებას, ყიდულობს ინვენტარს და აფართოებს კაფეს.

Phaser 3 + TypeScript + Vite. მენიუები — უბრალო HTML/CSS. ყველა გრაფიკა — კოდით
გენერირებული SVG (`scripts/assets` → `public/assets`).

## რა არის თამაშში

**დღის ციკლი:** დილის საწყობი (მარაგის ყიდვა, ბიუჯეტის ამოცანა) → დილის მომზადების ამოცანა →
სამუშაო დღე (ბურგერის აწყობა ბუშტის მიხედვით, გრილი, სასმელი/ფრი/ნაყინი, სალარო: ჯამი,
ხურდა მონეტებით, ანგარიშის გაყოფა) → საღამოს ანგარიში (შემოსავალი, ხარჯი, მოგება — ბავშვი
თვითონ ითვლის; 1 კლასში დიდი ჯამი ნაწილ-ნაწილ) → შემდეგი დღე (თუ მიზანი შესრულდა).

**მათემატიკა:** ~25 სახეობის ამოცანა კლასების მიხედვით (შეკრება, გამოკლება, უცნობი
შესაკრები, შედარება, მიმდევრობა, გამრავლება, გაყოფა ნაშთით, დრო, წილადები, პერიმეტრი,
მრავალნაბიჯიანი), რამდენიმე ფორმულირებით; ადაპტური სირთულე; შეცდომაზე — ვიზუალური
მინიშნება, მეორეზე — ამოხსნა ნაბიჯ-ნაბიჯ; 1 კლასში — 3 ვარიანტიდან არჩევა.

**განვითარება:** მაღაზია (მოწყობილობა, დეკორი, რეცეპტები), კაფეს 4 დონე, მეორე ფილიალი,
„ყველაფერი ააშენე!" ზეიმი. დღის დავალებები (ფული — ბიზნესიდან, ვარსკვლავები — მათემატიკიდან),
15 ბეჯი, დღის მოვლენები (ფესტივალი, მზიანი დღე, წვიმა, კრიტიკოსი).

**ჩემი ანგარიში:** კაფეს სახელი, ბეჯები, სიზუსტე მოქმედებებით, **ვარჯიში** (5 ამოცანა
სუსტ მოქმედებაზე), მოგების დიაგრამა, დღეების ისტორია.

**სხვა:** პირველი დღის სწავლება (თავიდან ნახვაც შეიძლება), ხმით კითხვა (ქართული ხმა),
მზარეულის არჩევა, მხოლოდ ჰორიზონტალური ეკრანი ტელეფონზე, დაყენებადი აპი (PWA) და
**ოფლაინ რეჟიმი** (`public/sw.js`), მასწავლებლის პანელი (კლასები, PIN-ები, სიზუსტე, სუსტი მხარე).

## შესვლა (ოფლაინ რეჟიმი)

ახლა მონაცემები ინახება მოწყობილობის localStorage-ში. პირველ გაშვებაზე იქმნება
სატესტო დემო კლასი — მისი კოდი, მოსწავლეები, PIN და მასწავლებლის ანგარიში
ჩაწერილია ფაილში [`src/data/demo.ts`](src/data/demo.ts).

* **მოსწავლე:** კლასის კოდი → სახელი სიიდან → 4-ნიშნა PIN.
* **მასწავლებელი:** ელფოსტა + პაროლი → კლასის შექმნა (6-სიმბოლოიანი კოდი, დონე 1–4),
  მოსწავლეების დამატება (PIN ჩანს ერთხელ), PIN-ის აღდგენა, სიზუსტე ოპერაციებით.
* **სტუმარი:** თამაში შესვლის გარეშე (ძველი შენახვაც ამით გრძელდება).

ოფლაინ რეჟიმი ერთი მოწყობილობისთვისაა (PIN/პაროლი ინახება SHA-256 ჰეშით).
რეალური დაცვისთვის — Supabase.

## Supabase (ღრუბელი)

საიტი (GitHub Pages) Supabase-ის პროექტს **burger-cafe** იყენებს: მასწავლებლის
ანგარიშები, კლასები, მოსწავლეები და პროგრესი ღრუბელში ინახება და ნებისმიერი
მოწყობილობიდან ჩანს. სტუმრის თამაში ისევ მხოლოდ ამ მოწყობილობაზეა.

* რეჟიმს ირჩევს `src/data/index.ts`: თუ build-ს აქვს `VITE_SUPABASE_URL` და
  `VITE_SUPABASE_ANON_KEY` (`.env.production`) → [`src/data/supabase.ts`](src/data/supabase.ts),
  თორემ ოფლაინ (`npm run dev` ლოკალურად ოფლაინ რეჟიმშია, დემო კლასით DEMO42).
* ლოკალურად ღრუბლით გაშვება: `npx vite --mode production`.
* სქემა: [`supabase/schema.sql`](supabase/schema.sql) — ცხრილები, ფუნქციები და Row Level
  Security (მოსწავლე ხედავს მხოლოდ საკუთარ მონაცემებს, მასწავლებელი — მხოლოდ თავისი
  კლასისას). PIN ინახება bcrypt-ით, 5 შეცდომის შემდეგ — 1 წუთით ბლოკი.
* Authentication: Email (დადასტურებით) მასწავლებლებისთვის, Anonymous sign-ins —
  მოსწავლეებისთვის. Site URL: `https://kokrine.github.io/burger-cafe1/`.
* მოსწავლის პროგრესის ასლი ლოკალურადაც ინახება: ინტერნეტი თუ გაწყდა, თამაში
  გრძელდება და ხაზზე დაბრუნებისას აიტვირთება.
* `.env.production`-ში მხოლოდ **publishable** გასაღებია (ბრაუზერისთვის). secret /
  service_role გასაღები რეპოში არასდროს ჩაწერო.
